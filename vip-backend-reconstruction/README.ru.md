# GOD PREDITOR · backend-реконструкция

Это рабочая независимая реализация серверных ответов для разработки своей
страницы. **Исходная закрытая модель VIP/AI сайта не получена.** Новый код
не выдаёт себя за неё: ответы содержат `reconstruction:true`,
`originalServerModel:false`, `calibrated:false`.

Реальный AI/LLM здесь не подключён. Эндпоинт анализа использует опубликованные
BASIC-правила, а не выдуманные ответы AI. Его балл не равен шансу выигрыша.

## Быстрый запуск

Нужен Node.js 24 или новее. Внешних зависимостей нет; `npm install` не нужен.

Для проверки без подключения к базе:

```sh
npm run demo
```

Адрес: `http://127.0.0.1:8787`. Демо использует искусственную историю и явно
возвращает `source:"synthetic_demo"`. Она не смешивается с реальной базой.

Для нашей или другой Supabase:

1. Создайте `.env` по образцу `.env.example`.
2. Заполните `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`.
3. Укажите существующие таблицу и поля времени/номера источника.
4. Запустите `npm start`.

По умолчанию адаптер читает `luckyjet_rounds` с полями `id`, `coefficient`,
`round_timestamp`, `source_seq`, фильтрами `completed=true`, `estimated=false`.
Он использует только GET, фиксированный снимок и точные курсоры; настройки
базы, RLS и данные не меняет. По умолчанию берётся до 2000 последних строк;
`HISTORY_LIMIT` можно увеличить до 10000. Это не загрузчик всей многомесячной базы.

Полный снимок кешируется на 15 секунд, параллельные чтения объединяются.
В `.env` не нужны `service_role`, закрытые ключи или сессии стороннего сайта.
Приложение использует уже разрешённый чтением доступ publishable/anon-ключа.

По умолчанию сервер слушает только localhost. Для внешнего адреса требуется
свой `API_TOKEN`; клиент отправляет `Authorization: Bearer <API_TOKEN>`.
Для браузера на другом сайте добавьте точный Origin в `ALLOWED_ORIGINS`.
Не публикуйте свой API_TOKEN в общем публичном интерфейсе: разработчик должен
настроить подходящую авторизацию перед многопользовательским размещением.

## API

### `GET /health`

Проверка запуска и флага демо. Не подтверждает наличие свежих данных Supabase.

### `GET /api/vip?game=luckyjet`

Возвращает поля, которые ожидает VIP-интерфейс:

```js
{
  sampleSize, fresh, dataCutoff, avgRoundSeconds,
  thresholds: [{
    threshold, count, frequencyPct, avgGapMinutes,
    estimatedNextAt, probNext3MinPct,
    probNext3MinPctInterval95, estimateStatus, etaStatus
  }],
  reconstruction: true,
  originalServerModel: false
}
```

Цели по умолчанию: 40×, 200×, 500×. Игра должна совпадать с `GAME` — история
разных игр и источников не объединяется.

Время и вероятность рассчитаны новой моделью, описанной ниже. Если данных
недостаточно, `null` означает отсутствие оценки; нельзя отображать его как 0%.
`fresh` описывает возраст последней записи. Доступность каждой оценки нужно
проверять по `estimateStatus` / `etaStatus`, а не только по `fresh`.

### `GET /api/analysis?game=luckyjet`

Берёт историю из настроенной Supabase и применяет публичный BASIC-алгоритм.
Активное BASIC-окно сохраняется в памяти сервера до окончания, как в исходной
функции. Повторные запросы не сдвигают его начало. Состояние разделено по игре
и источнику; при устаревании или разрыве истории оно сбрасывается. После
перезапуска сервера рассчитывается новое окно.

### `POST /api/analysis`

Анализ истории, переданной клиентом:

```js
{ game: "luckyjet", rounds: [{ id, coefficient, timestamp }] }
```

Максимум 200 раундов, время — Unix UTC в миллисекундах. Нужны минимум 20
свежих раундов в последнем непрерывном фрагменте. При недостатке данных или
устаревании возвращается HTTP 422 с причиной.

Успешный ответ содержит `estimatedCoef`, `category`, `confidence`, `rationale`,
`analyzed`, `dataCutoff`, `estimatedAt`, `windowMs`, а также
`aiModelUsed:false`, `confidenceType:"heuristic_rule_score"`.
Статистики минут/часов BASIC используют UTC, как в опубликованном коде.
Поле `auxiliaryHint.heuristicScore` — балл правила, не вероятность события.

### `POST /api/validate-window`

```js
{ target: 100, start, end, avgRoundSeconds: 30, rounds }
```

Проверяет **`start <= timestamp <= end`** оригинальной публичной функцией VIP.
Результат: `validated`, `failed`, `pending` или `unknown`. Событие до начала
окна не засчитывается. Для проигрыша нужны опорные раунды до/после окна и
допустимые промежутки; при нехватке истории результат остаётся неизвестным.

## Формулы новой VIP-реконструкции

История разбивается на непрерывные фрагменты: разрыв больше пяти минут или
неположительный интервал завершает фрагмент. Частота `frequencyPct` считается
по всей доступной выборке. Текущая оценка использует только последний фрагмент:
нужны минимум 200 раундов и последняя запись не старше 180 секунд.

Для цели T:

```text
p = число результатов >= T / число раундов текущего фрагмента
m = 180 / средний интервал между раундами в секундах
P(хотя бы одно событие за будущие 3 минуты) = 100 * (1 - (1 - p)^m)
```

Предполагаются независимые раунды и постоянная частота. Приводится
преобразованный интервал Wilson 95%. Он отражает выборочную неопределённость
в рамках предположений, а не доказанную точность прогноза. Если событий нет,
точечная оценка подавляется, верхняя граница неопределённости сохраняется.

Экспериментальный ориентир времени:

```text
estimatedNextAt = время последнего события >= T + медиана интервалов между событиями
```

Для него нужны минимум пять событий в текущем фрагменте. Если ориентир уже
прошёл, возвращается `null` и `etaStatus:"overdue"`. Время искусственно вперёд
не переносится. Длительное отсутствие большого X само по себе не повышает
шанс независимого следующего раунда. При недостатке данных ожидаемо могут
отсутствовать окна — это не подменяется постоянными «сигналами».

## Подключение страницы и userscript

`client-adapter.mjs` предоставляет `getVip`, `analyze`, `validate` для нашего
обычного JSON API. Пример:

```js
import {createClient} from './client-adapter.mjs';
const api = createClient({baseUrl:'http://127.0.0.1:8787/', token:'YOUR_OWN_API_TOKEN'});
const stats = await api.getVip('luckyjet');
```

Старый TanStack `/_serverFn/<hash>` — другой транспорт. Он не перехватывается
и не выдаётся за исходный сервер. Разработчику нужно заменить место вызова
сервера на адаптер и корректно показывать состояния с `null`.

## Что сохранено, а что написано заново

- `vendor/basic-original.mjs` — выделенный опубликованный BASIC-код.
- `vendor/vip-state-machine-original.mjs` — опубликованная проверка VIP-окон.
- `vip-model.mjs`, `normalize.mjs` — наша открытая реконструкция и нормализация.
- `supabase-feed.mjs`, `server.mjs`, `client-adapter.mjs` — новый адаптер и HTTP API.
- `basic-analysis.mjs` — новая обвязка оригинальных BASIC-правил, без LLM.

Приватная серверная формула, обучение AI и точность оригинального сервиса
не восстановлены. Реконструкция не содержит автоставок или отправки сообщений.
Старые страницы и файлы проекта не меняются.

Проверки: `npm test`. Реальная Supabase проверена отдельно без записи в базу;
пример результата находится в `verification/real-source-result.json`.
